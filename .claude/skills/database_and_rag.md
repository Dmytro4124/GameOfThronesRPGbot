# Skill: Database, RAG & Infrastructure

## 1. Робота з Google Sheets (gspread)
- **Синхронність:** Бібліотека `gspread` є блокуючою (синхронною). **УСІ** виклики до неї (читання/запис) повинні бути загорнуті в `asyncio.to_thread()`.
- **Таблиці:** `TAB_USERS` (профілі), `TAB_HOUSES` (інформація про доми), `TAB_CHARACTER` (шаблон), `TAB_KNOWLEDGE` (база знань), `TAB_NPC` (персонажі).
- **Профіль гравця:** Зберігається як серіалізований JSON-рядок у 3-й колонці таблиці `TAB_USERS`. Не намагайся розпарсити його по окремих комірках.

## 2. Архітектура RAG (Knowledge Base)
- **Модель:** `gemini-embedding-2-preview` (доступ через `genai.Client`).
- **Кешування (КРИТИЧНО):** Щоб не спалити квоти API, вектори кешуються локально.
  - Використовується масив `numpy` (`lore_embeddings.npy`).
  - Валідність кешу перевіряється через MD5 хеш поточного стану таблиці (`lore_hash.txt`).
- **Пошук:** Використовується евклідова відстань (`np.linalg.norm`). Поріг відсікання: `< 1.2`.

## 3. Система NPC (Anti-Hallucination)
- **Кешування:** NPC кешуються в пам'яті словником `NPC_CACHE`, згруповані за `Location` та `Scene`.
- **Автокорекція імен:** При оновленні NPC використовується `difflib.get_close_matches` з порогом `0.65`.
- **Анти-родинний запобіжник:** Логіка розбиває ім'я на слова і жорстко перевіряє перше слово (ім'я), щоб не сплутати персонажів з одного Дому (наприклад, Дейнеріс і Візеріс). Не "спрощуй" цю логіку.
- **Зовнішнє API:** Якщо NPC не знайдено локально, йде запит до зовнішнього API "Ice & Fire".
